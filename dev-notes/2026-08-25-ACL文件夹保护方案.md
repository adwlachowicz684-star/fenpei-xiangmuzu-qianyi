## 一、需求定义

对主界面当前选中的项目组/项目文件夹实施系统级 ACL 保护：

1. **单按钮入口**：现有侧边栏「锁定解锁」按钮（`LockToggleCommand`，Ctrl+L）升级为
   「ACL 锁定」——点击弹出设置弹窗，不再直接 toggle。
2. **原 lock 功能并入弹窗**：「账面固定」（加入 `config.Locked`，清除无效时跳过、不可删除）
   成为弹窗勾选项之一，**强制勾选、无法取消**（走此弹窗即至少账面锁定）。
3. **逐项权限勾选 + 预设档位按钮**：档位一键设置组合并清掉档外选项。
4. MCP 同步暴露状态与开关；监控告警兜底外部改动。
5. 定位：**防呆不防黑客**——常规 agent 写入被内核拒绝即达成目的；主动拆锁由告警暴露。

## 二、交互设计

### 「ACL 保护设置」弹窗（仿现有新拟物弹窗风格）

```
┌─ ACL 保护设置 ─────────────────────────┐
│ 目标：E:\...\xxx  [项目组|项目 徽章]      │
│                                          │
│ ☑ 账面固定        （强制勾选，禁用取消）    │
│ ☐ 防删除          （Deny Delete 子树递归） │
│ ☐ 防写入          （Deny 全部写入→只读）   │
│                                          │
│ 档位: [仅固定] [防删除(推荐)] [只读保护]   │
│ 监控告警: [开]                            │
│                                          │
│        [应用]  [解除全部保护]  [取消]      │
└──────────────────────────────────────────┘
```

- 档位映射：
  - 仅固定 = 账面 only（无 ACL，等价旧 LockToggle 行为）
  - 防删除 = 账面 + Deny Delete
  - 只读保护 = 账面 + Deny Delete + Deny Write
- 重命名随防删除自动被拦（重命名需源文件 Delete 权限），不设独立项。
- 已受保护的路径再点按钮 → 弹窗回显当前勾选状态，可调整或「解除全部保护」。
- 卡片标记：标签右侧追加**暗金盾牌图标**（复用 `LockBrush` 色系，区别于现有账面小锁），
  ToolTip 如「ACL 已保护·防删除」。
- 按钮文案改「ACL 锁定」，图标换盾牌/锁样式，快捷键 Ctrl+L 与 ShortcutCatalog 文案同步更新。

### 数据模型（config 新增，旧格式完全兼容）

```json
"folderLock": {
  "watchAlerts": true,
  "items": [
    { "path": "E:\\...\\某组", "denyDelete": true, "denyWrite": false }
  ]
}
```

- 路径粒度登记；项目组/项目通用（后续可做卡片右键批量操作）。
- 账面固定仍复用既有 `config.Locked`（不动旧格式）。

## 三、技术实现

### 1. Services/FolderLockService.cs（新）

- Deny ACE 身份：Everyone（WellKnown SID `S-1-1-0`）：
  - 防删除：`FileSystemRights.Delete`，InheritanceFlags = ObjectInherit|ContainerInherit；
    目录自身另加 `Delete | DeleteSubdirectoriesAndFiles`。
  - 防写入：`WriteData | AppendData | WriteAttributes | WriteExtendedAttributes`（同继承）。
  - **永不触碰**：Read 类、WRITE_DAC、TakeOwnership——保证所有者永远能进得去改得回来。
- API：`Protect(path, denyDelete, denyWrite)` / `Unprotect(path)` / `GetState(path)` /
  `WithUnlock(path, Action)`（临时摘除本工具 ACE → 执行 → finally 恢复）。
- `SweepResidual(paths)`：启动自愈——enabled=false 或路径已从 items 移除时，
  清扫残留 Everyone-Deny ACE（此类 ACE 只可能由本工具引入）。
- junction 说明：穿透访问在链接解析后的真实目标上做 ACL 检查，仍被拦截 ✓。
- csproj 需加 NuGet：`System.IO.FileSystem.AccessControl`（.NET 8 显式引用）。

### 2. Services/FolderWatchService.cs（新）

- 每受保护路径一个 FileSystemWatcher（Created/Changed/Deleted/Renamed，
  IncludeSubdirectories，InternalBufferSize=64KB），事件去抖聚合后回调。
- Deleted/Renamed 尝试 → 日志区红色告警（谁在删、被拒痕迹）；Created/Changed → 信息级。
- 工具自身 WithUnlock 窗口期抑制误报。

### 3. GUI 改动点

- `MainWindow.xaml`：侧边栏按钮文案/图标/ToolTip；卡片盾牌图标绑定（两处卡片模板 1132/1322 附近）。
- 新建 `Views/AclLockDialog.cs`（参考 PromptDialog/IconPickDialog 的代码构造风格 + 全局新拟物资源）。
- `MainViewModel`：`AclLockCommand` 替换 LockToggleCommand（保留键位）；folderLock 读写存盘；
  监控事件接 LogViewModel；工具自身删除类写点（remove_link 等）经 WithUnlock 包裹。
- `ShortcutCatalog`：「锁定 / 解锁」显示名 →「ACL 锁定」。

### 4. MCP 第 7 组「保护」（McpToolCatalog + McpServer）

- `lock_status`：列出 items 与每组 ACL 实际生效状态。
- `lock_set(path, deny_delete, deny_write)`：开关某路径保护。
- get_manual / get_status 同步扩充；工具描述告知 AI：
  「组内删除已被系统级拦截，如需删除请请示用户在 GUI 解除」。

## 四、自救五层套路（锁了自己目录怎么办）

| 层 | 机制 |
|---|---|
| 1 Fail-open | WithUnlock 窗口中崩溃 → 只是变回未锁，绝不反锁死 |
| 2 启动自愈 | SweepResidual 清扫残留 Everyone-Deny 后按 items 重建 |
| 3 GUI 兜底 | 弹窗「解除全部保护」一键全解 |
| 4 手动兜底 | 文档化命令：`icacls "<目录>" /remove:d *S-1-1-0`（TIPS + README 记录） |
| 5 权限底线 | 不碰 READ / WRITE_DAC / 所有权，所有者永远可自救 |

## 五、边界与已知限制

- 主动改 ACL 可绕过（Deny 不含 WRITE_DAC，否则自解无门）；高特权进程可绕 → 监控告警暴露。
- 防写入档开启时，工具自身写点（deploy_skill 写 SKILL.md、FolderIconService 写 desktop.ini）
  必须经 WithUnlock 包裹，否则自伤。
- backup 只读源不受影响；备份目录不在保护范围。
- 资源管理器手动删受保护内容也会失败并可能弹系统错误框——属预期行为。
